lispresen とは

三つの特長

  1. 読めない文字を出さない
    • 収まらないスライドは、文字を縮めずにエラーにする
  2. スライドのコードを動かす
    • Lisp、Scheme、Clojure をその場で編集して実行する
  3. どこで描画しても同じ出力
    • インタプリタ、JVM、WASM、SBCL が同じバイト列を書く
5

lispresen とは

なぜS式で書くのか

  • 差分をコードと同じようにレビューできる
  • 構造が明示される
    • インデントに意味を持たせない
    • 見えないスタイルがない
  • プログラムで生成したデッキもただのリスト
6
Markdown や WYSIWYG のツールと比べて話す。

lispresen とは

デッキは読むだけで評価しない

トップレベルのフォームを一つずつ read する。

  • マクロも #. も使えない
  • どのバックエンドでも同じ言語になる
  • 信頼できないデッキも安全に描画できる
7
フォームごとに読むので、診断には行番号が付く。

レイアウトはツールが決める

文字の大きさは自動で決まる

スライドごとに、収まる最大の段を選ぶ。

  1. どのスライドも 1920 x 1080 (:aspect :4x3 なら 1440 x 1080) で組み、画面に合わせて拡大する
  2. 本文は 56px から始め、必要なときだけ 40px まで下げる
  3. 40px でも収まらなければ、縮めずにエラーとして報告する

出力と始め方

描画は文字列から文字列への関数

(lispresen:render source &key theme runtime read-file embed page-image)
;; => (values html diagnostics image)
  • 入出力をしないので、CLI からもブラウザからも呼べる
  • 整数だけで計算するので、どこでも同じバイト列になる

使い方

ネイティブ実行ファイル

JVM も rontolisp も要らない実行ファイルを、リリース lispresen-0.1.0-SNAPSHOT で配布している。

プラットフォームファイル
macOS (Apple Silicon)lispresen-darwin-arm64
Linux (x86_64)lispresen-linux-amd64
Linux (arm64)lispresen-linux-arm64
  • 実行権を付け、PATH の通ったディレクトリに lispresen の名前で置く
  • macOS でブラウザからダウンロードしたファイルは隔離され、起動すると止められる
78

試す

ネイティブ実行ファイル

$ BASE=https://github.com/making/rontolisp/releases/download
$ curl -fLO $BASE/lispresen-0.1.0-SNAPSHOT/lispresen-darwin-arm64
$ chmod +x lispresen-darwin-arm64
$ sudo mv lispresen-darwin-arm64 /usr/local/bin/lispresen
$ lispresen --version
{"version": "0.1.0-SNAPSHOT", "gitCommit": "3b9b214"}

curl と wget で取得したファイルは隔離されない。ブラウザでダウンロードしたファイルは xattr -d com.apple.quarantine で隔離を外す。

出力と始め方

コマンドライン

lispresen DECK [-o OUT] [--theme NAME] [--runtime URL|hosted|none]
               [--embed] [--check] [--strict]
lispresen new FILE [--lang ja|en] [--force]
lispresen --version
  • - で標準入力から読み、標準出力に書く
  • --embed で画像を埋め込み、ファイル一つで完結させる
  • --version は版とビルドしたコミットを JSON で出す
  • 終了コードは 0 が成功、1 がエラー、2 が使い方の誤り

始め方

$ lispresen new talk.lisp

  • 診断には行番号が付く。その行を直して描き直す
  • 見本はこのデッキ、lispresen/examples/intro.lisp
