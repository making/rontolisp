# Deleted todo items

A row is added whenever a `.todo/NNN-*.md` file is removed, recording the commit that
removed it. The commit itself is the detail; this table is the index. `Status` is
exactly `completed` or `cancelled` -- no prose. `Model` is the
model that did the WORK -- which is not always the model that removed the file (an item
can outlive the model that wrote it), and when the work was done by a subagent it is that
subagent's own model, NOT the orchestrating session's (a subagent inherits its parent's
`Co-Authored-By` trailer, so the trailer is a hint, not the answer).

Two sessions can number an item the same way before either can see the other. The
number then names two different items, and the LATER commit's side renumbers its live
file (`.todo/633` and `.todo/634` both happened on 2026-09-02). A row already written
KEEPS its literal path even when the number was later ceded -- `git show <Commit>~:<File>`
below is the invariant, and the path in that commit is the answer. Read a row by its
full file name, never by its number alone.

To read a deleted item's content, take its row's `Commit` and `File` and run
`git show <Commit>~:<File>` -- `Commit` is the commit that removed the file, so its
parent still contains it. Every row must keep this invariant. Each `Commit` cell is
also linked as `https://github.com/making/rontolisp/blob/<commit>~/<file>` so the
deleted item can be read directly on GitHub.

Rows are split by month under `.todo/history/` to keep this index short. Append a new
row to the file for the month the deletion happens in (`.todo/history/YYYY-MM.md`),
creating that file with the same header/table shape as an existing one if the month is
new, and add a row below for it. A month file carries no entry count and the index's
`Entries` column is not maintained per deletion -- appending the row is the whole job.
