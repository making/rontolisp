# 仕様との差異

- **末尾呼び出しが真に末尾になるのはループに変換できる場合だけです**: 名前付き `let`、`do`、
  および末尾位置での自己呼び出し。相互再帰や高階の末尾呼び出しはスタックを消費します。
  互いを呼び合う 2 手続きは、JVM の既定スタックでは深さ 2,000 から 5,000 の間で、
  インタプリタと WebAssembly では 10,000 から 100,000 の間でオーバーフローします。
- **`call/cc` は脱出専用です。** 継続は、その `call/cc` の実行中に 1 回だけ呼べます。
  再突入はないため、ジェネレータやコルーチンは作れず、`dynamic-wind` の `before` は
  ちょうど 1 回だけ実行されます。
- `call-with-values` は、両引数が `lambda` 式として書かれているとき直接束縛になります。
  それ以外の形はリストを経由します。
- ループ -- 名前付き `let` や、自分自身への呼び出しがすべて末尾呼び出しである手続き --
  が呼び出しで終わるとき、その呼び出しの最初の値だけを返します。`(let loop ((l l)) (if (null?
  l) (f) (loop (cdr l))))` は `f` がいくつ値を返しても 1 つの値を返します。`(values ...)`
  で終わるループはすべての値を返します。
- **例外は巻き戻しの後で捕捉されます。** `guard` は本体を抜けた後で節を実行するため、
  どの節も選ばれなければ `guard` からオブジェクトを再び発生させます。外側のハンドラは本体の
  `raise-continuable` を再開できません。`with-exception-handler` のハンドラは `raise`、
  `raise-continuable`、`error` の場所で実行されますが、組み込み手続きのエラーでは `thunk`
  を抜けた後で実行されます。WebAssembly では、機械がトラップするエラー（ペアでないものの
  `car`、範囲外の添字）は発生させられずにプログラムを終了します。捕捉されない `error` は
  メッセージと irritant を、捕捉されない `raise` はそのオブジェクトを表示してプログラムを
  終了します。
- パラメータオブジェクトを引数付きで呼ぶとエラーです。Gauche は値を設定します。`eval` の
  中の `parameterize` は名前を挙げて拒否されます。
- どの節も受け付けない個数の引数で `case-lambda` を呼ぶと、エラーオブジェクトが raise
  されます。`eval` の中の `case-lambda` は名前を挙げて拒否されます。
- ポートはテキストかバイナリのどちらか一方で、両方ではありません: 文字列ポートの
  `binary-port?` は `#f` です（Gauche のポートは両方です）。標準のポートはテキストポート
  なので、`read-u8`、`write-u8` などのバイナリ手続きにはバイトベクタポートの引数が必要
  です。`char-ready?` と `u8-ready?` は常に `#t` を返します。
- レコードは Common Lisp の `#S(...)` 構文で表示されます。`equal?` はレコードを同一性で
  比較します。
- `write` は `'x` を `(quote x)` と、未規定値を `#!unspecific` と表示します。未規定値は
  1 つのオブジェクトで、条件としては真です。
- `exit` は囲んでいる `dynamic-wind` の `after` を実行してから、そのステータスでプロ
  セスを終了します; その場で終了するのは `emergency-exit` のみです。
- 複素数はありません: `(sqrt -4)`、`(log -1)`、`(asin 2)` は手続き名を挙げたエラーで
  プログラムを終了します。
- エラーメッセージには Common Lisp の名前（`CAR`）が出ます。
- `utf8->string` は、正しい UTF-8 の列を始めないバイトをエラーにせず、そのバイト値を
  コードとする文字に復号します。

## 未対応

`define-library`、ファイルポート（`(scheme file)`）、
その他のライブラリ、`|...|` 識別子、
`+inf.0` / `+nan.0` の読み取り。構文に関するものは、ファイルを読む時点で名前を挙げて拒否されます。
