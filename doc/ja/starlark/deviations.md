# 仕様との差異

準拠は設計上部分的です。動作が
[仕様](https://github.com/bazelbuild/starlark/blob/master/spec.md)と異なる箇所はここに
挙げたとおりで、どのバックエンドでも同じです。

## 動作が異なる点

**文字列はコードポイントの列です。** `len`、添字、スライスは Unicode のコードポイントを
数えます。仕様の 2 つの文字列モデルは、UTF-8 のバイトか UTF-16 のコード単位を数えます。
`hash` は仕様どおりの値です。

```starlark
print(len("𝄞"), "naïve"[2], "日本語"[::-1], hash("𝄞"))
```

```
1 ï 語本日 1772394
```

**`print` は標準出力に書きます。** 仕様は出力先をホストに任せており、Bazel では
標準エラー出力です。

**寛容な方言です。** `if` と `for` をトップレベルに書けます。グローバル変数に 2 回以上
代入できます。関数は自分自身を呼び出せます。Bazel はこの 3 つをすべて拒否し、Go の実装は
それぞれをオプションにしています。

**トップレベルの関数は、その `def` より上から呼び出せます。** 仕様では、`def` 文が
実行されるまではエラーです。

```starlark
print(double(21))

def double(x):
    return x * 2
```

```
42
```

**代入前の変数を読んでも、エラーになるとは限りません。** ローカル変数は `None` に
なります。グローバル変数はエラーで、メッセージは Common Lisp のもの（`The variable y is
unbound`）です。

そのほかの差異は次のとおりです:

- range のスライスはリストを返します。range は開始値を付けて `range(0, 5)` と印字されます。
- `isalpha`、`isdigit`、`isalnum`、`isspace` は ASCII の文字だけを判定します。
- エラーはプログラムを終了させます。標準エラー出力に `Unhandled condition: ` とメッセージが
  出て、終了ステータスは 0 以外になります。メッセージにファイル名と行番号は含まれません。
  文面は Go の実装に合わせています。
- 数千要素のリスト式、タプル式、辞書式は JVM のクラスにコンパイルできません。JVM の
  メソッドに許される大きさを超えるためです。インタプリタと WebAssembly では動きます。

## まだないもの

- `load` と `b"..."` リテラル。どちらも、プログラムの実行前にその位置で拒否されます。
- `bytes` 型と `set` 型、およびそれらを作る組み込み関数。
- 凍結。ファイルの実行が終わっても、値は不変になりません。
- REPL、プレイグラウンドでの言語選択、このセクションのページの Run セル。
- 1 つのプログラムの中での、Starlark のファイルと Common Lisp のファイルの間の呼び出し。
  互いに相手がどう見えるかは、まだ決まっていません。
