# listen

`(listen &optional stream)`

指定された入力ストリーム (引数なしなら標準入力) から文字またはバイトを即座に読めるなら `t`、そうでなければ `nil` を返します。ブロックしません。これは `available()`/`ready()` に相当する問い合わせであり、プロトコル実装が予期しないデータを検出するために使います (cl-postgres は過大な SSL 応答の検出に用います)。

インタプリタと JVM ではソケットに対してカーネルの受信バッファを見るため、答えは正確です。WASM の `--component` バックエンドのソケットは、ホストがすぐに渡せるものを答えます。すでに読み込んだチャンクに残っているバイトか、ホストが待たずに応じる読み取りです。ホストに渡すものがなければその読み取りを取り消すので、何も消費しません。ホストが先に動く必要のあるバイト（届く途中の相手のデータ）は、プログラムが次に待ったあと（`sleep`、ブロッキング読み取り、`usocket:wait-for-input` のポーリング）に初めて見えます。そのため、ポーリングは間に待ちを挟んで行い、待ちのないループで回さないでください。ネイティブ実行ファイルのソケットは、読み込み済みのチャンクにバイトが残っているかを答えます。文字列入力ストリームはすべてのバックエンドで残り文字の有無を答えます（unread した文字も数えます）。Preview 1 の WASM ではそれ以外のストリームに対する `listen` は呼び出し時にエラーを通知します。非ブロッキングの問い合わせ手段がないためです。

```console
(listen)          ; => NIL, 標準入力に未読データがない場合
```
