# directory

`(directory pathspec &key (resolve-symlinks t))`

`pathspec` に一致するファイルの真名 (truename) を、重複を除き `string<` でソートして
返します。ホストがどの順でエントリを返してこようと、同じプログラムはどのバックエンドでも
同じ答えを表示します。一致するものがなければ `nil` を返し、通知することはありません。

**ワイルドな名前コンポーネント**を含む場合はディレクトリを一覧し、パターンに一致した
ものを残します。`*` は任意個の文字、`?` はちょうど 1 文字にマッチします。各返り値は
[`truename`](truename.md) が返すのと同じそのエントリの真名なのでそのまま開くことができ、
ディレクトリには末尾に `/` が付きます。

```lisp
(directory "no-such-directory/*.*")   ; => NIL
```

真名は絶対パスです。相対 pathspec は SBCL と同じく `*default-pathname-defaults*` と
マージし、作業ディレクトリの下に置きます。`/w` で実行し、`a.txt`、`b.txt` と
サブディレクトリ `sub/`、`empty/` を含むディレクトリ `d` がある場合:

| pathspec | 結果 |
|---|---|
| `"d/*.*"` | `(#P"/w/d/a.txt" #P"/w/d/b.txt" #P"/w/d/empty/" #P"/w/d/sub/")` — すべて |
| `"d/*.txt"` | `(#P"/w/d/a.txt" #P"/w/d/b.txt")` |
| `"d/?.txt"` | `(#P"/w/d/a.txt" #P"/w/d/b.txt")` |
| `"d/*"` | `(#P"/w/d/empty/" #P"/w/d/sub/")` — 名前がワイルドで型が**無い**ので、型を持たないものだけ |
| `"d/a*"` | `NIL` — 同じ規則。`a.txt` は型を持ちます |

**ワイルドでない pathspec は自分自身を指します**。これは Common Lisp と同じで、
`"d/a.txt"` はファイルが存在すれば `(#P"/w/d/a.txt")` を返し、ディレクトリはディレクトリ形式の
自分自身を返します（`"d"` も `"d/"` も `(#P"/w/d/")`）。**ディレクトリを一覧するのは
`"d/*.*"` であって `"d/"` ではありません。**

**シンボリックリンク**はリンク自身の名前で照合し、その真名で返します。そのため、1 つの
ファイルを指す 2 つの名前は 1 度だけ返ります。指す先が存在しないリンクはリンク自身を
返します。`:resolve-symlinks nil` を渡すと、照合した名前をそのまま返します。この場合も
ディレクトリへのリンクには末尾の `/` が付き、指す先が存在しないリンクは除かれます。
`/w` で実行し、ディレクトリ `d/`（中に `a.txt`）、`d` へのリンク `ln`、`d/a.txt` への
リンク `al`、何も指さないリンク `dang` を含むディレクトリ `t/` がある場合:

| 呼び出し | 結果 |
|---|---|
| `(directory "t/*")` | `(#P"/w/t/d/" #P"/w/t/d/a.txt" #P"/w/t/dang")` |
| `(directory "t/*" :resolve-symlinks nil)` | `(#P"/w/t/al" #P"/w/t/d/" #P"/w/t/ln/")` |

**pathspec の `.` と `..` は、一覧の前に綴りの上で取り除きます**。SBCL と同じく、
どちらのモードでもそうします。`(directory "./*.txt")` の答えは `#P"/w/a.txt"` です。
`(directory "t/ln/../*")` は、`ln` がどこを指していても、名前 `ln` を含むディレクトリ
`t/` を一覧します。[`truename`](truename.md) は逆に、リンクの後の `..` をリンクの指す先から
数えます。

**ワイルドなディレクトリコンポーネント**を含む場合は、名前を照合する前に接頭辞を
展開します。`*` はちょうど 1 階層、`**` はサブツリー全体を辿ります。Common Lisp と
同じく `**` は 0 階層にも一致するので、起点ディレクトリ自身のファイルも返ります。

| pathspec | 結果 |
|---|---|
| `"d/*/*.lisp"` | `d/` の 1 階層下にある `.lisp` ファイル |
| `"d/**/*.lisp"` | `d/` とその下のどこかにあるすべての `.lisp` ファイル |
| `"d/**/"` | `d/` 自身と、その下のすべてのディレクトリ |

上記の結果はいずれも、同じツリーに対して SBCL が返すものと一致します。

## バックエンドサポート

4 バックエンドすべてで、それぞれ 1 つのプリミティブを通して動きます。インタプリタは
ソースローダー抽象（ファイルシステムを持たないホスト、たとえばブラウザプレイグラウンドでは
失敗せずに `nil` を返します）、JVM は `java.io.File.list`、WASM は両モードとも WASI の
`fd_readdir` です。Preview 1 は実際のホスト関数に、`--component` は
`wasi:filesystem` の `read-directory` 上のアダプタに束縛されます。WASM モジュールは
パスはプリオープンされたディレクトリに対して解決されます。相対パスは最初の 1 つ、絶対パスは名前がそのパスの最長の接頭辞になるプリオープンディレクトリに対して解決されます。そのため `--dir` を付けて実行してください。
付けない場合は何にも一致しません。答えが絶対パスになるのは、[`probe-file`](probe-file.md)
と同じくモジュールが作業ディレクトリを知っている場合だけです。`wasmtime run --dir .` では
表の答えから `/w/` が除かれます。

`.` と `..`（自身と親）のエントリは、どのバックエンドでも返りません。WASM では
[`probe-file`](probe-file.md) と同じく、モジュールがプリオープンされたディレクトリを
通して読めるリンクだけを解決します。

`uiop:directory-files`、`uiop:subdirectories`、`uiop:collect-sub*directories` は、
本家 UIOP が SBCL に求めるとおり `:resolve-symlinks nil` を付けてこの 1 つの関数で
定義されています。
