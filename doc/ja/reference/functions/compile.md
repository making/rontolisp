# compile

`(compile name definition)`

リテラルの `(lambda ...)` 定義を、空のレキシカル環境で評価して関数に変換します。`name` が nil なら関数そのものを返し、シンボルの `name` を渡すとその名前のグローバル定義としてもインストールし、Common Lisp と同様に名前を返します。rontolisp の `compile` はネイティブコードを生成しません — 定義時のコード構築イディオムをロード可能にするために存在します。特に、クラスメタオブジェクトに対してメソッドを定義する引数なしの定義(オブジェクトマッパーの `(funcall (compile nil `(lambda () ,code)))` イディオム。`code` はクラスから計算した値を閉じ込めます)は、定義時のメソッド構築として実行されます。

コンパイルされたプログラム(JVM / WASM 出力)では、このメソッド構築イディオムはコンパイル時に展開されてプログラムに継ぎ足され、同じ呼び出しの実行時再実行は no-op になります。プログラム自身のトップレベル定義が `compile` に渡す定義(ライブラリがクラスやメソッドを定義する途中でラムダ式から関数を作るもの。contextl のレイヤードアクセサなど)は事前にコンパイルされます。コンパイラはプログラムのコンパイル時にそれらの定義を実行し、そこで `compile` に渡された定義をそれぞれプログラム内のコンパイル済みコードにします。定義が保持するオブジェクト(総称関数、クォートされたリスト)は実行時の呼び出しから取ります。それ以外の実行時 `compile` 呼び出しは、定義をプログラムの [`eval`](eval.md) ランタイムで評価します — コンパイル済みプログラムはコンパイラを持たないためです([コンパイル済み `eval` の制限](../../guides/eval-limitations.md)を参照)。

```lisp
(list (funcall (compile nil '(lambda (x) (* x x))) 7)
      (compile 'my-inc '(lambda (x) (+ x 1)))
      (my-inc 41)) ; => (49 MY-INC 42)
```
