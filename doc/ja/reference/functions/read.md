# read

`(read &optional stream)`

単一の S 式を読み取って解析します。引数がない場合は標準入力から読み取ります。`open` または `with-open-file` で開いたストリームを与えると、そのストリームから読み取ります。空行とコメントのみの行はスキップされ、データムは 1 行に収まる必要があり、EOF では `nil` を返します。3 つすべてのバックエンドで動作しますが、読める構文は同じではありません。インタプリタは完全な Lisp リーダーを使いますが、コンパイル系バックエンドが出力するリーダーは**より狭く**、リスト（ドット対を含む）、`'`、`#'`、文字列、シンボル、数値だけを理解します。インタプリタが読む `#` ディスパッチ構文（`#S(...)`、`#(...)`、`#\a`、`#nA(...)`、`#x10`）はそこでは理解されず、通常のシンボルとして読まれ、残りのテキストはその後続として読まれます。この範囲の中では JVM リーダーは JDK と完全に同等で、WASM リーダーはさらに狭い範囲です（31 ビット整数、10 進浮動小数点数で、多倍長整数や指数表記はありません）。

```console
(print (read))
```

標準入力から `(+ 1 2)` という行を読み取ると、リスト `(+ 1 2)` に解析され、`print` がそれをそのまま出力します。入力の終端では `read` は `nil` を返します。実行時に読まれるシンボルはリーダーの[大文字化](../../guides/reader-case.md)に従い、ユーザーのシンボルも標準の名前も同様に大文字化されます(畳み込みはありません)。これはすべてのバックエンドで同一です。
