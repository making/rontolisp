# probe-file

`(probe-file pathname)`

ファイルが存在するかどうかを答えます。存在すればそのパス名を、存在しなければ `nil` を返します。これは何も開かずにこの問いに答える唯一のファイル操作であり、存在しないパスで失敗しない唯一の操作でもあります。`open`（したがって `with-open-file`）はどのバックエンドでもエラーを通知します。そのエラーを捕捉する方法も使えますが、より重くなります。`handler-case` は WASM バックエンドを例外モードにし、`--no-gc` は捕捉自体を拒否するため、素直な検査のほうが可搬な綴りです。4 つすべてのバックエンドで動作します。[`truename`](truename.md) はこの関数の通知する版です。

成功時に返されるパス名は、SBCL と同じくファイルの真名 (truename) です。パスに含まれるシンボリックリンクをすべて解決し、`.` と `..` を取り除いたもので、[`truename`](truename.md) が返すパス名と同じです。`d` が `x` へのリンクなら、`(probe-file "d/f.txt")` は `#P"x/f.txt"` です。絶対パスにはしません（相対パスには作業ディレクトリからの相対パスを返します。WASM モジュールは作業ディレクトリを知りません）。ディレクトリは綴りによらずディレクトリ形式で返ります。`(probe-file "d")` も `(probe-file "d/")` も、`d` へのリンクも `#P"d/"` です。末尾に `/` を付けて綴ったファイルは `/` なしで返ります。指す先が存在しないリンクは、SBCL と同じくリンク自身を返します。引数はパス名と名前文字列のどちらの綴りでも受け付けます。パスの解釈は `open` と同じで、インタプリタと JVM ではプロセスの作業ディレクトリ基準、WASM ではプリオープンされたディレクトリ基準です（相対パスは最初の 1 つ、絶対パスは名前がそのパスの最長の接頭辞になるプリオープンディレクトリ。`--dir` を付けて実行してください）。ディレクトリも存在するものとして扱われます。[`uiop:file-exists-p`](uiop-file-exists-p.md) は、ディレクトリ以外については同じ答えを返します。

WASM では、モジュールがプリオープンされたディレクトリを通して読めるリンクだけを解決します。どのプリオープンよりも上にあるリンクは綴りのまま残ります（macOS の `/tmp` は `/private/tmp` へのリンクなので、`--dir /tmp` では `/tmp/f.txt` の答えは `#P"/tmp/f.txt"`、`--dir /` では `#P"/private/tmp/f.txt"` です）。絶対パスを指すリンクはたどりません（WASI ホストが拒否します）。そのようなパスは存在しないものとして扱われます。いずれの場合も、答えはモジュールが開けるパスです。

```console
(if (probe-file "config.lisp")
    (load "config.lisp")
    (print "no config"))
```

ここではファイルが存在する場合にのみ読み込みます。`probe-file` がなければ、ファイルが無い場合は `else` 側に進むのではなくプログラムが異常終了してしまいます。
