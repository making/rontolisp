# declare

`(declare declaration...)`

`special` 以外の宣言はプログラムの計算結果を変えません。`declare` フォーム全体は nil に評価され、引数は評価も検証もされないため、標準のあらゆる宣言（`ignore`、`ignorable`、`type`、`optimize`、`inline`、`special` など）を本体のどこにでも書け、他の Common Lisp 処理系向けに書かれたソースコードを変更なしにロードできます。

4 つの宣言ファミリはコンパイルに影響します。本体の先頭の `(declare (special ...))` は、標準の CL と同じく、そのフォームが確立する、列挙された変数の束縛をダイナミックにし、その本体の中の参照にダイナミックな束縛を読ませます。内側にある同名の束縛は、それ自体がスペシャルと宣言されない限りレキシカルです。WASM バックエンドでは、配列型を指名する `type` 宣言 — `(simple-array (unsigned-byte 8) (*))`、`simple-vector` など — や、その配列か nil を指名する宣言 — `(or null simple-vector)` — により、その表現専用の要素アクセサを直接エミットするため、コンパイル済みモジュールは小さく速くなります。要素型が整数の範囲である汎用の配列 — `(simple-array (signed-byte 64) (*))` — の要素は、整数の算術の中で生の機械整数として読みます。64 ビットに収まる整数の範囲を指名する宣言 — `(signed-byte 32)`、`(unsigned-byte 16)`、`(integer 0 255)`、`(mod 10)`、それらの `deftype` — では、変数や `(the ...)` フォームの値を、他の値のための汎用の経路なしに生の機械整数として扱うため、それに対する算術が小さく速くなります。ここでは `typep` にとってすべての整数が `fixnum` なので、`fixnum` は範囲を指名しません。さらに JVM バックエンドでは、浮動小数点型を指名する `type` 宣言 — `double-float`、`single-float`、`float` — により、宣言されたローカル変数を生の `double` スロットに保持し、その算術を unboxed な機械命令にコンパイルするため、特に JIT のウォームアップ前が速くなります。上記の整数の範囲の宣言では、融合された整数算術がその値を他の値のための汎用の経路なしに扱うため、コンパイル済みクラスが小さくなります。また、主に整数の算術で読まれる宣言されたローカル変数を生の `long` スロットに保持するため、それを計算する文がオブジェクトを割り当てず、コンパイル済みクラスが速くなります。上記の配列型の宣言では、融合された整数算術がその表現の要素を生の機械整数として読み書きし、そう宣言された変数への `(setf (aref var i) value)` が文字列の場合を省くため、コンパイル済みクラスが小さく速くなります。*正しい*宣言が結果を変えることはありません。*偽の*宣言（Common Lisp では未定義動作）は WASM では宣言された値を扱う箇所でトラップし、JVM では宣言された読み書きの箇所で捕捉可能なエラーを通知し（宣言した範囲の外でも 64 ビットに収まる整数や、別の表現の配列は宣言がないものとして計算し、宣言された配列として書き込まれた文字列ではエラーを通知します）、インタープリタでは引き続き無視されます。

```lisp
(let ((x 10))
  (declare (type integer x) (optimize (speed 3)))
  (* x 2)) ; => 20
```

```lisp
(defun declare-eg (y)
  (declare (special y))
  (let ((y t))
    (list y (locally (declare (special y)) y))))
(declare-eg nil) ; => (T NIL)
```
