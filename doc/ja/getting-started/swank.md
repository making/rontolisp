# SWANK (SLIME、SLY、Lem)

`rontolisp --swank` は Common Lisp の [REPL](repl.md) を SWANK で提供します。SWANK は
Emacs の [SLIME](https://slime.common-lisp.dev) が話すプロトコルです。SLIME から分かれた
[SLY](https://github.com/joaotavora/sly) と [Lem](https://lem-project.github.io) の Lisp
モードのプロトコルにも答えます（[後述](#sly-and-lem)）。サーバは localhost
で待ち受け、`--swank=PORT` で別のポートを指定しない限り SWANK と同じ 4005 番を使います
（`--swank=0` は空いているポートを使います）。起動すると SWANK 自身の `create-server` と
同じ行を出力します:

```console
$ rontolisp --swank
;; Swank started at port: 4005.
```

Emacs で `M-x slime-connect RET 127.0.0.1 RET 4005 RET` と入力すると、SLIME の REPL が
このサーバにつながります。サーバが話すのは SLIME 2.32 と通常の `slime-fancy` 拡張のプロトコル
です。別のバージョンの SLIME は、どの SWANK に対しても行うのと同じく、最初に「Versions differ」
と確認します（`slime-protocol-version` を `'ignore` にすると確認を省けます）。

| SLIME での操作 | rontolisp の動作 |
|---|---|
| REPL | 入力のフォームを順に評価し、最後のフォームの値をすべて表示する。`*` `**` `***`、`/` `//` `///`、`+` `++` `+++` を設定する。出力は書かれたそばから送る。`(read-line)` は REPL に入力した行を読む。`in-package` は REPL のパッケージを変える |
| `C-x C-e`、`C-M-x`、`C-c :` | フォームをバッファのパッケージ（その `in-package`）で評価し、値をエコー領域に表示する |
| `C-c C-c` | トップレベルのフォームをコンパイル（rontolisp では評価）し、ノートを付ける。ノートになるのは、フォームが送出した警告、評価を止めたエラー、読み込みが止まった位置、どこにも定義のない関数の呼び出し |
| `C-c C-k`、`C-c C-l` | ファイルを読み込む（ファイルコンパイラはなく、読み込みがコンパイルにあたる）。ノートは同じものをファイル上の位置に付ける |
| `TAB`、`C-M-i`、`C-c M-i` | 接頭辞が補完するシンボル。`-` で区切った部分ごとに照合する（`m-v-b`）か、あいまいに照合する |
| エコー領域 | カーソルを囲むオペレータの引数リスト。入力中の引数に印を付ける。変数ならその値 |
| `C-c C-d d`、`C-c C-d f` | シンボルの説明。何を名付けているか、ラムダリストとドキュメント文字列、変数の値 |
| `C-c C-m`、`C-c M-m` | マクロの展開。1 段だけ、またはフォーム中のすべてのマクロ |
| `C-c M-e`（macrostep） | マクロフォームをその場で 1 段ずつ展開し、展開結果の中のマクロフォームに印を付ける |
| `M-.` | カーソル位置の名前の定義。`C-c C-c`、`C-c C-k`、`load`（`C-c C-l`、プログラムの `load`、ASDF システム）が実行した場所（関数、マクロ、総称関数とそのメソッド、変数、クラスとそのアクセサ、構造体とその関数、パッケージ）。REPL で入力した定義には SBCL と同じく場所がない。組み込みのオペレータには定義の場所がない |
| `C-c C-w c` `w` `r` `b` `s` `m` `a`、`C-c <`、`C-c >` | サーバの実行中にコンパイル、ロード、REPL 入力したコードの相互参照。関数を呼ぶ側と関数が呼ぶ先、スペシャル変数を参照、束縛、代入する側、マクロを展開する側、クラスに特化したメソッド |
| `C-c I` | インスペクタ。リストや配列の要素、ハッシュテーブルのエントリ、インスタンスのスロット、シンボルが名付けているもの、数の表現、クラス、スロット定義、総称関数とそのメソッド、パッケージとそのシンボル、パス名を示し、各部分を続けて調べられる。インスペクタのアクション（エントリの削除、シンボルの束縛解除、スロットの設定、メソッドの削除など）も使える |
| エラー | シグナルされた位置でデバッガ（SLDB）を開く（後述） |
| `C-c C-b` | 実行中の評価をデバッガで止める。`c` で評価を続ける |

SWANK の `:spawn` 方式と同じく、エディタの要求はそれぞれ専用のスレッドで、REPL の要求は
1 つのスレッドで実行します。各要求は、要求が指定したパッケージで読み込み、評価します。
そのため、REPL でループを実行している間に `C-c C-c` で再定義した関数は、ループが次に呼ぶ
時点で新しい定義になります。すべての接続が 1 つのイメージを共有します。

## デバッガ

どのハンドラも処理しないエラーは、シグナルされた位置で、何も巻き戻さないうちに SLIME の
デバッガを開きます。そのため、プログラムが確立したリスタートはすべて有効なまま残ります:

```console
boom 1
   [Condition of type SIMPLE-ERROR]

Restarts:
 0: [RETRY] Retry SLIME REPL evaluation request.
 1: [*ABORT] Return to SLIME's top level.
 2: [ABORT] abort thread (#<THREAD "repl-thread" RUNNING {5E}>)

Backtrace:
  0: (EVAL (ERROR "boom ~a" 1))
```

`q` はトップレベルに戻ります。`a` は最初の abort リスタートを、`c` は continue リスタート
（`cerror` や割り込みのもの）を起動し、番号は一覧のそのリスタートを起動します。番号で選べる
リスタートには `restart-case` や `with-simple-restart` が確立したものも含まれます。フレームは
値を待っている関数で、引数とともに表示します。フレームの上で `t` を押すとそのローカル変数
（パラメータと、待っている位置で束縛されている変数）を一覧し、`e` はそれらを参照できる状態で
式を評価します。デバッガの中で起きたエラーは次のレベルを開き、そのレベルの `ABORT`
リスタートは一つ下のレベルに戻ります。`C-c C-b` も実行中の評価を同じようにデバッガで止めます。
`sleep` や入力の読み込みを待っている評価も止まります。

バッファやファイルのコンパイルは、エラーをノートにしてデバッガを開きません。フレームの再実行、
フレームからの値の返却、ステップ実行はできません。フレームのソース位置と catch タグは表示
しません。`with-simple-restart` と `cerror` のリスタートの説明は、引数を埋め込まないフォーマット
制御文字列のまま表示します。

## SBCL との違い

トレースとプロファイル、プレゼンテーション、作業ディレクトリの変更には答えません。相互参照の
対象はエディタからコンパイルしたコードだけで、REPL で入力した関数には移動先がありません。
パッケージはキーワードとして表示し（`:CL-USER`）、マクロの展開は 1 行で、コンディションは
報告文とともに（`#<SIMPLE-ERROR "boom 1">`）表示します。値や名前は rontolisp の表示に従います（SBCL が
`COMMON-LISP-USER::F` と書くところは `CL-USER::F` です）。サーバはインタプリタでだけ動きます。

## SLY と Lem

同じサーバが SLY と Lem にも答えます。各要求には、それを送ったクライアントのプロトコルで
答えるので、3 つのエディタを同時に接続できます。SLY では `M-x sly-connect RET 127.0.0.1 RET
4005 RET` で SLY の REPL が開きます。サーバが話すのは SLY 1.0.43 のプロトコルで、別の
バージョンの SLY は最初に「Versions differ」と確認します。Lem では同じホストとポートを
`M-x slime-connect` に与えると Lem の REPL が開きます（Lem 2.3.0 で計測）。

上の表のうち REPL、評価、コンパイル、補完、エコー領域、説明、展開の行は、どちらにもそれぞれの
キーで当てはまります。SLY の REPL は数値をほかの表記と並べて表示し（`3 (2 bits, #x3, #o3,
#b11)`）、あいまいに補完します（`mvbind` で `multiple-value-bind` が見つかります）。Lem の
補完は候補ごとに種類、引数リスト、説明を表示し、`C-c Return` はマクロを 1 段展開します。どちらも
デバッガは持たず、エラーは割り込みと同じく評価を中断します。`M-.`、相互参照、インスペクタは
SLIME でだけ計測しています。SLY の
スティッカーとトレースダイアログ、Lem の表示した値の検査には答えません。

## 実行中のプログラムから

インタプリタで実行するプログラム（ファイル、`-e`、REPL）は、組み込みの `swank` システム
（[システム（asdf）](../guides/asdf-systems.md)）の `swank:create-server` で同じサーバを
自分のイメージ上に起動できます。プログラムはそのまま実行を続け、SLIME からその中身を調べたり
再定義したりできます。

```console
$ cat app.lisp
(asdf:load-system "swank")
(defvar *requests* 0)
(swank:create-server :port 4005 :dont-close t)
$ rontolisp app.lisp
;; Swank started at port: 4005.
```

キーワード引数は SWANK と同じで、SWANK と同じ行を `*error-output*` に出力し、ポート番号を
返します。
`:dont-close t` ではすべての接続を受け付け、すぐに戻ります。指定しない場合（SWANK の既定）は
最初の接続を待ち、その後ポートを閉じます。`:interface` は待ち受けるアドレスです（既定は
localhost）。`(swank:stop-server 4005)` はポートを閉じますが、確立済みの接続は続きます。
最後まで実行し終えたプログラムも、ポートが閉じてエディタが切断するまでサーバを提供し続けます。
SLIME から終了するとプロセスが終了します。コンパイルしたプログラムには提供するインタプリタが
ないので、`swank:create-server` はエラーを送出し、`swank:stop-server` は `nil` を返します。
