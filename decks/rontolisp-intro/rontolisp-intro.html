rontolisp とは

Java で実装した Common Lisp のサブセット

一つのソースを、三つの実行モードで動かす。

  • インタプリタ REPL とファイル実行。ツリーウォークで評価する
  • JVM コンパイラ .class や .jar を出力する
  • WASM コンパイラ wasm-GC を使った .wasm を出力する

コアライブラリは外部依存を持たない。JVM と WASM のバイトコードも、ASM などのライブラリを使わずに出力する。

4

rontolisp とは

なぜサブセットなのか

  • インタプリタ、JVM、WASM で同じように動く
  • ランタイムのメタオブジェクトプロトコルなしでバイトコードへ直接コンパイルできるよう、言語を小さく保つ
  • そのため、完全な Common Lisp の機能の多くを意図的に省いている

doc/ja/guides/missing-features.md

5

rontolisp とは

まず動かしてみる

このスライドのコードはブラウザの中の rontolisp が実行する。クリックで編集し、Run で実行する。

(defun fact (n)
  (if (= n 0) 1 (* n (fact (- n 1)))))
(print (fact 10))

Run で 3628800 が出る

6
Run を押す。続けて (fact 30) に書き換えて実行し、多倍長整数になることを見せる。

インストールと最初の実行

インストール

リリースページのビルド済みバイナリを PATH に置く。JVM は要らない。

$ URL=https://github.com/making/rontolisp/releases/download/0.1.0-SNAPSHOT
$ wget $URL/rontolisp-darwin-arm64
$ chmod +x rontolisp-darwin-arm64
$ sudo mv rontolisp-darwin-arm64 /usr/local/bin/rontolisp
$ rontolisp --version
  • Linux の x86-64 と ARM64 向けもある
  • Java 25 以降があれば、実行可能 JAR でも動く
8

インストールと最初の実行

REPL

引数なしで起動すると REPL になる。定義は入力をまたいで残る。

$ rontolisp
CL-USER> (+ 1 2)
3
CL-USER> (defun fact (n) (if (= n 0) 1 (* n (fact (- n 1)))))
FACT
CL-USER> (fact 10)
3628800
CL-USER> (quit)

プロンプトには現在のパッケージ名が出る。括弧が閉じるまで複数行を読む。

ファイルを実行する

;; program.lisp
(defun square (x) (* x x))
(print (square 5))
(print (square 12))
$ rontolisp program.lisp

25
144
$ rontolisp -e "(print (+ 1 2))"

言語

プログラムもリスト

コードは S 式で書く。S 式はリストなので、マクロはリストを組み立ててコードを作る。

(defmacro twice (&body body) `(progn ,@body ,@body))
(print (macroexpand-1 '(twice (princ "hi "))))
(twice (princ "hi "))

言語

CLOS とコンディション

(defclass circle () ((r :initarg :r :reader r)))
(defclass square () ((side :initarg :side :reader side)))
(defgeneric area (shape))
(defmethod area ((c circle)) (* 3 (r c) (r c)))
(defmethod area ((s square)) (* (side s) (side s)))
(print (mapcar #'area (list (make-instance 'circle :r 2)
                            (make-instance 'square :side 3))))
(handler-case (/ 1 0)
  (division-by-zero () :infinity))

言語

Scheme のフロントエンド (実験的)

.scm のファイルを、R7RS-small の一部として読む。

(import (scheme base) (scheme write))
(define (count-up n)
  (let loop ((i 0) (acc '()))
    (if (= i n)
        (reverse acc)
        (loop (+ i 1) (cons (* i i) acc)))))
(display (count-up 5))

言語

言語はファイルごとに決まる

拡張子言語
.lisp .asdCommon Lisp
.scmScheme
.clj .cljcClojure
それ以外--source-language で指定する
  • 一つのプログラムに複数の言語のファイルを混ぜられる
  • どの言語も同じコアフォームに変換され、すべてのバックエンドで動く
  • Scheme と Clojure は実験的。動かし続けたいものは Common Lisp で書く

バックエンド

一つのパイプラインから三つの実行モードへ

  • 言語の違いは最初の変換で吸収する
  • バックエンドは Scheme や Clojure の名前を知らない
20

バックエンド

出力の拡張子でバックエンドを選ぶ

$ rontolisp hello.lisp                                # インタプリタ
$ rontolisp hello.lisp -o Hello.class && java Hello   # JVM
$ rontolisp hello.lisp -o hello.jar && java -jar hello.jar
$ rontolisp hello.lisp -o hello.wasm && wasmtime run hello.wasm
$ rontolisp hello.lisp -o hello-c.wasm --component && wasmtime run hello-c.wasm
$ rontolisp hello.lisp --native -o hello && ./hello   # ネイティブ

どの形でも (print (+ 1 2)) は 3 を出力する。

21

バックエンド

JVM と WASM

JVM

  • .jar は java -jar で動く
  • Java のライブラリにもできる

WASM

  • 既定は WASI Preview 1
  • --component で WASI 0.3
  • --no-wasi でインポートなし
  • --no-gc で任意のエンジン向け (数値と文字列のみ)
22

バックエンド

ネイティブ実行ファイル

--native は、WASM 出力を wasmtime でマシンコードにプリコンパイルし、小さなランナーの後ろに付ける。

  • 実行に wasmtime も JVM も要らない
  • 起動は約 10 ms
  • --native-target で Linux の x86_64 と aarch64、macOS の aarch64 向けを作れる

doc/ja/compiling/native.md

バックエンド

インタプリタは試行錯誤に使う

  • 即座に起動し、コンパイラと同じ意味で実行する

連携とライブラリ

Java 連携

java パッケージが、リフレクションで任意の Java API を呼ぶ。

(java:call (java:new "java.lang.StringBuilder" "ab") "length")  ; => 2
(java:static "java.lang.Math" "max" 3 7)                        ; => 7
(java:field "java.lang.Integer" "MAX_VALUE")                    ; => 2147483647
  • JVM 上のインタプリタと、コンパイルした .class で動く
  • WASM はホストのオブジェクトを表せないので、コンパイルを拒否する
28

連携とライブラリ

ASDF で複数ファイルのプロジェクトを読む

;; my-app.asd
(defsystem :my-app
  :depends-on (:base)
  :serial t
  :components ((:file "package")
               (:file "main")))
  • .asd はプレーンなデータとして解析する
  • 依存するシステムから順に読み込む
  • --system-path で探す場所を足す
  • インタプリタ、JVM、WASM のどれでも同じように動く
