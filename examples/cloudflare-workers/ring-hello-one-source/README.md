# ring-hello-one-source — one Ring file, five hosts, this one included

There is **no Clojure in this directory**. The program is
[`clojure/ring-hello.clj`](../../clojure/ring-hello.clj) *itself* — a Ring
handler with `ring.util.response` builders and the `wrap-params` /
`wrap-keyword-params` middleware, served by `ring.adapter.rontolisp/run-server`.
The same file binds a socket on the interpreter and the JVM, deploys into a
Servlet container as a war, and serves under `wasmtime serve`; here it is
compiled for a host that **calls an export** instead of handing over a socket.

```bash
./build.sh          # ../../clojure/ring-hello.clj -> src/worker.wasm + src/worker.js
npx wrangler dev    # http://localhost:8787
npx wrangler deploy
```

```console
$ curl http://localhost:8787/
Hello from Ring on rontolisp, curl/8.5.0
$ curl 'http://localhost:8787/greet?name=Ann'
Hello, Ann!
$ curl -d name=Bob http://localhost:8787/greet
Hello, Bob!
$ curl -H 'content-type: text/plain' --data-binary 'héllo' http://localhost:8787/echo
HÉLLO
$ curl -i http://localhost:8787/home
HTTP/1.1 302 Found
Location: /
$ curl http://localhost:8787/nope
no route for GET /nope
```

A urlencoded `POST /echo` answers empty: `wrap-params` has already read the body
to parse the form, as under Ring's Jetty adapter.

## One source, five hosts

`run-server` lowers to the same transport function Clack's `:server :rontolisp`
calls, and the transport is chosen at compile time:

| Build | Who owns the port | How it runs |
| --- | --- | --- |
| interpret | the program binds it | `rontolisp ../../clojure/ring-hello.clj` (`:port 3000`) |
| `-o App.class` | the program binds it | `java -cp . App` |
| `-o app.war` | the Servlet container | `cp app.war $CATALINA_HOME/webapps/` |
| `-o app.wasm --component` | the wasi:http host | `wasmtime serve -S cli=y app.wasm` |
| `-o worker.wasm --no-wasi` | Cloudflare | this directory: the generated `src/worker.js` calls `handle-request` |

`:port` and `:host` apply only where the program owns the socket.
[`examples.yaml`](../../examples.yaml) pins the JVM class, the war, the
component and this module, all built from the one file.

Everything else is documented once, in [`../hello-clack`](../hello-clack): where
the [`handle-request` export comes from](../hello-clack/README.md#the-javascript-half-is-not-hand-written-either)
and the [limitations](../hello-clack/README.md#limitations) of the `--no-wasi`
build.

## What's in here

| File | Purpose |
| --- | --- |
| [`../../clojure/ring-hello.clj`](../../clojure/ring-hello.clj) | **The whole program** — not in this directory, deliberately |
| [`build.sh`](build.sh) | `--no-wasi --optimize=size --emit-js-glue` over that file |
| [`src/index.js`](src/index.js) | Three lines over the generated `worker()`, byte-identical to every `hello-*` sibling's |
| [`src/worker.js`](src/worker.js) | The boundary, GENERATED by `--emit-js-glue` and pinned by `HostGlueEmitterTest`. It is `../hello-clack`'s file less the entropy seeding: the program draws no random number, so `--optimize=size` drops the seed hook and the glue does not call it. Do not edit; `./build.sh` rewrites it |
| `src/worker.wasm` | A build product — run `./build.sh` first |

## Rebuilding

```bash
./mvnw clean package -DskipTests   # from the repository root
examples/cloudflare-workers/ring-hello-one-source/build.sh
```
